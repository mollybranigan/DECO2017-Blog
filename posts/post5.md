# Note
One thing that has changed significantly throughout this project is my understanding of what is actually feasible within the time and technical constraints of the assignment. Early on, my group felt confident that our idea was relatively simple. Compared to large social media platforms, an exchange student discussion hub did not seem overly complicated. However, once we started building the homepage and main discussion area, we realised that even basic features take much longer than expected.

The biggest example of this was the homepage discussion section. On paper, it seemed straightforward. We thought it would mainly involve displaying posts and responses in a clean format. In reality, it took multiple days of work just to create a functional version of the main discussion page. A large part of this came from issues we had not fully considered during the planning stage.

One challenge was simply structuring the layout in a way that felt usable. We had to think about how posts should appear, how responses should nest underneath them, and how users would navigate between discussions without the page becoming visually overwhelming. Even small design choices, such as spacing, alignment, and navigation placement, ended up taking much more time than expected because they affected the overall usability of the platform.

Another issue was that we underestimated the complexity of interaction. Initially, features like filtering discussions by course or home country sounded relatively easy to implement. However, once we began thinking about how data would actually flow through the application, the complexity increased. Each filtering option requires additional structure behind the scenes, including how posts are categorized, stored, and retrieved from the database.

This experience made me rethink some of our earlier assumptions about scope. At the beginning of the semester, I tended to judge feasibility based mostly on whether an idea sounded simple conceptually. Now I realise that even relatively small interaction features can require significant development time when combined together.

Because of this, my thinking around priorities has changed. Earlier in the project, I was interested in adding features like private messaging and more advanced personalization. At this stage, I think creating a stable and functional discussion system is more important than trying to implement every possible feature. A smaller number of polished features will likely create a stronger user experience than many incomplete ones.

This has also changed how I think about the relationship between design and development. A wireframe can make a system appear clean and manageable, but actually building it forces you to think through structure, data relationships, and interaction flow in much more detail. The process has made me more aware of how important it is to continuously reassess scope rather than treating early plans as fixed.

| Feature           | Initial Expectation | Actual Complexity              |
| Discussion Feed   | Simple layout       | Multiple days of work          |
| Replies/Responses | Easy interaction    | Complex structure/navigation   |
| Course Filtering  | Minor feature       | Requires database organisation |
| Messaging         | Small addition      | Significant extra complexity   |
